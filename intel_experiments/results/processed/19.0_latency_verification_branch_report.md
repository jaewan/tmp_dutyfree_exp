# Phase 19.0 CXL Latency Verification Branch

## Verdict

**HALT.** PMU attribution showed the 512 MB node-2 pointer chase is
LLC-dominated by the branch decision rule. Prefetcher ablation is now
available and did not reveal masked high latency: pf-off was slightly lower
than pf-on.

## Step 1: PMU Attribution

Command equivalent:

```bash
perf stat -e mem_load_retired.l1_hit,mem_load_retired.l2_hit,\
mem_load_retired.l3_hit,mem_load_retired.l3_miss,longest_lat_cache.miss -- \
  numactl --membind=2 --cpunodebind=0 -- \
  ./bench/victim/pointer_chase --cpu 0 --node 2 --wss 536870912 \
  --trials 1 --run-sec 10
```

Result:

| Metric | Value |
|--------|-------|
| WSS | 512 MB |
| LLC capacity | 60 MB |
| Latency | 205.24 ns |
| L1 hit | 213,163,258 |
| L2 hit | 3,138,780 |
| L3 hit | 20,726,493 |
| L3 miss | 5,560,062 |
| Longest-lat-cache miss | 52,010,730 |
| L3 miss fraction | 0.211517 |
| NUMA hugepage residency | N2 confirmed |

Decision rule:

```text
L3_MISS / (L3_HIT + L3_MISS) < 0.50 -> LLC-dominated, proceed Step 3
```

Observed fraction = 0.211517, so the branch proceeds to Step 3.

CSV: `results/processed/19.0_pmu_attribution.csv`

## Step 3: Prefetcher Ablation

After rerunning setup, `bench/victim/pointer_chase` had `cap_sys_rawio=ep`
and could disable MSR 0x1A4 internally.

Results, n=10 per condition at 512 MB:

| Case | Median ns | IQR ns | Min ns | Max ns |
|------|-----------|--------|--------|--------|
| CXL_512MB_pf_on | 163.67 | 7.44 | 159.64 | 213.66 |
| CXL_512MB_pf_off | 159.51 | 1.00 | 158.52 | 164.24 |

Prefetcher disable did not substantially increase latency. This rules out
the branch's "prefetchers were masking much higher CXL latency" explanation
for this pointer-chase run.

Note: because `pointer_chase` now has `cap_sys_rawio`, Linux denies non-root
reads of that process's `/proc/PID/numa_maps`. The pf-off ablation therefore
records `numa_huge_n2=-1` rather than live residency evidence. Previous
non-capability runs with the same `numactl --membind=2` and benchmark
`--node 2` showed node-2 hugepage residency.

CSV: `results/processed/19.0_prefetcher_ablation.csv`

## MLC Cross-Validation

Intel MLC v3.12 was subsequently installed from Intel's official mirror:

```text
https://downloadmirror.intel.com/866182/mlc_v3.12.tgz
```

The tarball matched Intel's published SHA256:

```text
4B8F7685D71998DD5D445432AB40C2115158462BFCD359113AE551A84E250C50
```

MLC result:

```text
mlc --idle_latency -j2
Each iteration took 423.6 base frequency clocks (222.9 ns)
```

This is inside the revised [200 ns, 600 ns] validation range. Phase 19.0
CXL accessibility validation therefore passes by MLC.

## Conclusion

Evidence-grounded validation outcome:

1. PMU evidence does not confirm CXL-dominated pointer-chase accesses at
   512 MB, so average pointer-chase latency remains invalid as the gate.
2. Prefetcher ablation does not reveal masked high latency.
3. MLC cross-validation reports node-2 idle latency of 222.9 ns, validating
   CXL accessibility under the revised methodology.

Phase 19.1 may proceed after MLC validation, subject to the fresh AL-VL
reproducibility gate.
