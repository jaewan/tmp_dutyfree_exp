# Phase 19.1 Baseline Reproducibility Diagnosis

## Summary

Phase 19.1 remains halted. The immediate cause is that the fresh local baseline
used for bandwidth-matched Phase 19 (`AL-VL`, 1 local WB+prefetch aggressor)
has essentially zero tax, while the Phase 12 headline used 2 local aggressors
and produced +197%.

Diagnostics show:

1. The local aggressor binary is generating bandwidth.
2. The 32 MB victim is currently LLC-resident when quiescent.
3. The current platform is not the Phase 12 platform profile.
4. A literal Phase-12-style 2-aggressor rerun produces moderate tax, not the
   original +197%.

## Partial Phase 19.1 Observation

Recorded separately in `results/processed/19.1_partial_observation.md`:

```text
AC-VL n=30 mean=78.728 cycles/load, median=78.719
mean victim L3 miss fraction=0.013857
```

No interpretation is attached to this value because the local baseline failed.

## Step 1: Aggressor Bandwidth

Output: `results/processed/19.1_diagnosis_aggressor_bw.txt`

The local `stream_wb` aggressor reported:

```text
avg_bw_gbps = 14.234
```

iMC CAS read counters over 20 seconds were consistent with ~13-14 GB/s
aggregate read traffic. This rules out the simple "aggressor is not streaming"
failure mode for a 1-core local aggressor.

## Step 2: Victim L3 Miss Rate

Output: `results/processed/19.1_diagnosis_victim_l3.txt`

Named perf events for quiescent 32 MB victim:

```text
mem_load_retired.l3_miss = 9,721
mem_load_retired.l3_hit  = 246,989,079
mem_load_retired.l2_hit  = 2,104,682
cycles_per_load          = 77.023
```

L3 miss fraction:

```text
9721 / (246989079 + 9721) = 0.000039
```

The current 32 MB victim is effectively LLC-resident in quiescence.

## Step 3: MSR State

Output: `results/processed/19.1_diagnosis_msr_state.txt`

`rdmsr -p {0,1,2,3} 0x1A4` failed with `Operation not permitted` from this
non-root session. Benchmark binaries with `cap_sys_rawio` can manipulate MSRs,
but plain `rdmsr` cannot.

## Step 4: Environment Drift

Output: `results/processed/19.1_diagnosis_env_current.txt`

The environment no longer matches the Phase 12 preregistered platform:

```text
Expected: Intel Xeon Platinum 8462Y+, 32 physical cores/socket, 32 CHA tiles
Current:  Intel Xeon Platinum 8592+, 64 physical cores/socket, 64 CHA tiles
Current node0 CPU list: 0-63,128-191
Current L3: 640 MiB total, 2 instances
```

This is the strongest diagnostic result. The current machine/profile is not
the Phase 12 SPR profile recorded in `env/env_report.md`.

## Step 5: Code Drift

Output: `results/processed/19.1_diagnosis_codedrift.txt`

Since 2026-05-10, code changes touched new Phase 17/18 aggressors and scripts:

```text
bench/aggressor/random_chase.c
bench/aggressor/forced_turnover.c
exp/17_sf_saturation.py
exp/18_sf_forced_turnover.py
```

No commit in this window touched `bench/aggressor/stream_wb.c` or
`bench/victim/pointer_chase.c`.

## Step 6: Literal Phase-12-Style A@2 Reproduction

Output: `results/processed/19.1_phase12_literal_a2_repro.csv`

Fresh same-session checks:

| Check | n | Mean cyc/load | Median cyc/load | Tax vs QL |
|-------|---|---------------|-----------------|-----------|
| QL_REPRO | 10 | 76.952 | 76.944 | 0.0% |
| AL-VL_REPRO, 1 aggressor | 10 | 77.196 | 77.180 | +0.32% |
| Phase12-style A@2, 2 aggressors | 10 | 131.394 | 134.702 | +70.75% |

The literal 2-aggressor style still produces some interference, but it does
not reproduce the Phase 12 +197% headline.

## Diagnosis

The strongest supported explanation is environmental/platform drift, not a
simple aggressor binary failure:

- Aggressor bandwidth is present.
- The victim is far more cache-resident than the Phase 12 interpretation
  assumed.
- The current host reports a different CPU SKU/topology with much larger LLC
  resources: 8592+ / 64 cores per socket / 64 CHA tiles / 320 MiB L3 per socket,
  instead of the preregistered 8462Y+ / 32 cores per socket / 32 CHA tiles /
  60 MiB L3 per socket.
- Phase12-style A@2 gives +70.75%, not +197%, so the original result is not
  reproduced on the current platform state.

## Decision

Do not proceed with Phase 19.1. The DR3 denominator is invalid until the
baseline is either reproduced on the original Phase 12 platform/profile or the
study is explicitly re-baselined for the current 8592+ platform.
